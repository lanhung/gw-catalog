## 总结判断

1. 暂未发现 SIS LIGO noisy 数据本身存在 NaN/Inf、全零、shape 错误、主峰被裁剪等硬错误。
2. SIS noisy 与 pure 是逐样本对应的，但 LIGO noisy 噪声强度远大于纯信号，pure/noisy 相关性中位数只有约 0.02。
3. SIS 的 SNR 不低于 PM，反而更高；所以 SIS 差不是因为整体 SNR 比 PM 低。
4. SIS 和 PM 的源参数基本一致，主要差异来自 lens 分布，尤其 SIS 时延比 PM 长约两个数量级。
5. SIS LIGO noisy 的 waveform-only 崩溃不是局限于极少数异常样本；低 SNR、长时延、第二像相对较弱的桶更差，但即使高 SNR 桶也远未达到可用水平。
6. 工程代码中存在一个明确可疑点：普通 preprocess 分支训练增强 `np.roll` 没指定 `axis=-1`，对 LIGO detector×time 输入会按展平数组滚动，可能跨 detector 通道边界。这个点应该做 ablation 或直接修复后重训。

## 2. 工程代码是否有问题

### 2.1 L1/L2 partner 与 val/test ground truth

- `EvaluationSet` 中 catalog 顺序为 L1、L2、unlensed，见 `matchgw/data.py:287-289`。
- `pair_id` 按同一个 `lensed_idx` 的 local index 写入 L1/L2，见 `matchgw/data.py:291-294`。
- `ground_truth_partner` 用相同 `pair_id` 互指 L1/L2，见 `matchgw/data.py:315-325`。
- 因此评估阶段 partner 构造逻辑是自洽的。当前没有证据显示 val/test 的真实 partner 错位。

### 2.2 H1/L1 detector 顺序与 in_channels

- LIGO `.npy` 形状为 `(10000, 2, 98304)`，代码会自动识别 `in_channels=2`，见 `matchgw/pipeline.py:50-60`。
- `to_channels` 对二维输入使用 `x.reshape(-1, x.shape[-1])`，保留 detector×time 的通道结构，见 `matchgw/data.py:208-220`。
- 单探测器 SNR 两个通道 median 非常接近，且通道0>SNR通道1比例约 0.50，没有明显通道恒定错置迹象。

### 2.3 np.roll 跨 detector channel 风险

- 普通 preprocess 分支训练增强在 `matchgw/data.py:199-200` 使用 `np.roll(y, shift)`，没有指定 `axis=-1`。
- 对 LIGO 的 `(2, T)` 输入，NumPy 默认会 flatten 后滚动，这会把一个 detector 尾部片段卷到另一个 detector 开头，破坏 detector 间相位/时间关系。
- multiband 分支已经正确使用 `axis=-1`，见 `matchgw/data.py:248-249`。
- 当前主实验使用 `preprocess=bandpass`，走普通分支，因此这个问题真实存在于训练增强阶段。评估阶段没有 roll，所以它不会直接污染 test waveform，但会影响模型学到的表示。

### 2.4 zscore 与 peak_flip

- 普通分支使用全局 `zscore(x)`，对 LIGO 两个 detector 合并归一化，见 `matchgw/data.py:116-117` 与 `matchgw/data.py:255-257`。
- 这不一定是 bug，但会让强噪声通道影响另一个通道的尺度；建议与 per-channel zscore 做 ablation。
- `peak_flip` 用全局最大峰统一符号，见 `matchgw/data.py:120-124`。这可能破坏 detector 间物理相位符号，也建议与关闭/按参考通道 flip 做 ablation。

### 2.5 bandpass 40-580 的含义

- 当前 `spectral_preprocess` 中的 `bandpass_low/high` 是 rFFT bin index，不是物理 Hz，见 `matchgw/data.py:174-180`。
- 如果论文中表述为 40-580 Hz，需要重新按采样率换算；如果只是工程频域 bin，应明确写作 frequency-bin bandpass。

## 建议的下一步实验

1. 先修复普通 preprocess 分支的 `np.roll`：改为 `np.roll(y, shift, axis=-1)`，只重训 LIGO SIS noisy 50ep，与当前结果对比。
2. 做 per-channel zscore ablation：普通 bandpass 分支评估阶段和训练阶段都改为按 detector 通道归一化。
3. 做 `aug_flip=False` 或按固定 detector 通道 flip 的 ablation，确认全局 peak_flip 是否破坏 LIGO 双通道相位关系。
4. 把 bandpass 从 rFFT bin 改成真实 Hz 参数化，或在文档中明确当前是 bin 过滤。
5. 对 SIS LIGO noisy 分桶训练/重采样：提高低 SNR、长时延、低 `|mu1|/|mu0|` 样本权重，验证是否能提升 R@10。
6. 真实可用方案上，不应依赖 ra/dec oracle sky；需要继续提高 waveform->sky_map_overlap 预测质量，否则 sky 分支不能解释论文中的真实场景性能。
